# Extracting Requirements from Meetings

This skill guides you on how to transform raw meeting notes and transcripts into a high-fidelity "Artifact Blueprint" with a Technical Implementation Matrix and prioritized deliverables.

## Workflow

Copy this checklist and track progress:
- [ ] Step 1: Obtain the meeting notes or transcript (e.g., from Google Drive or local file).
- [ ] Step 2: **Check for Tabs**: If fetching from Google Docs, check if there are multiple tabs (e.g., Notes vs Transcript). Prioritize reading the transcript.
- [ ] Step 3: Apply the analysis prompt to extract the Technical Implementation Matrix, focusing on Pain Points and Implementation Tooling.
- [ ] Step 4: Map the extracted requirements to suggested artifacts and **prioritize them** (P0, P1, P2).
- [ ] Step 5: Present the structured Blueprint to the user using the template below.

## Analysis Prompt

Use the unified discovery and solutions architect system prompt defined in [discovery_analyst.md](file:///prompts/discovery_analyst.md) passing the target flag: `--format blueprint`.

## Gotchas & Pitfalls

- **Missing Context**: If a requirement doesn't have a clear "Why," flag it as a risk.
- **Ambiguity**: Distinguish between hard blockers and nice-to-haves.
- **Summaries vs Transcripts**: Summaries often hide technical complexity. Always look for the raw transcript if available.
- **Pain Points**: Pay special attention to past failures or comparisons with competitors mentioned in the transcript.

## Blueprint Template

Use this exact structure when generating the Artifact Blueprint:

```markdown
# Artifact Blueprint: [Customer Name] - [Project Name]

This blueprint was generated by analyzing the meeting [notes/transcript] from the "[Meeting Title]" meeting on [Date].

## Technical Implementation Matrix

### 1. The "What" (Functional Requirements)
- **Component**: [e.g., Secure Web Proxy, Cloud Armor]
- **Requirement**: [e.g., Layer 7 filtering, Whitelist mode]
...

**Final State Architecture**: [1-2 sentences summarizing the final state].

---

### 2. The "Why" (The North Star & Business Drivers)
- **[Component/Requirement]**: [Why is it needed? Security, compliance, timeline?]
...

---

### 3. The "How" (Technical Spec & Variables)
- **[Item]**: [Specific technical details, tags, protocols, tools]
...

---

### 4. The "When" (Sequence & Deadlines)
- **[Phase]**: [What happens when]
- **Deadline**: [Target date]
...

---

### 5. Objections & Friction Points
- **[Concern]**: [Description of concern and status]
...

---

## Citations & Key Statements

- **[Speaker Name] ([Role/Company])**:
    - **[[Timestamp]]**: [Key statement]
...

---

## Artifact Mapping & Prioritization

### 🚨 P0: Immediate Action (Critical Path)
**[🛠️ Codelab / 🧪 Demo / 📄 Whitepaper]: [Title]**
- **Topic**: [Brief description]
- **Focus**: [Bulleted list of steps or content]
- **Why**: [Reason for P0 priority]

### 📈 P1: Secondary Focus
**[🛠️ Codelab / 🧪 Demo / 📄 Whitepaper]: [Title]**
...

### 📚 P2: Deferred / Long-term
**[🛠️ Codelab / 🧪 Demo / 📄 Whitepaper]: [Title]**
...
```
